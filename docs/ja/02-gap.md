# 統合システムに不足している部分（ギャップ分析）

業務機能・技術アーキテクチャ・データモデルの 3 次元で、「PF × BioDB 統合プラットフォーム」が目標（設計→収集→保存→管理→分析→可視化）に対して不足している部分を列挙する。

## 1. 業務機能ギャップ

| ギャップ | 現状 | 説明 |
|---|---|---|
| **データ管理（研究/プロジェクトレベル）** | 無し | 「研究プロジェクト」の概念が無い；研究/実験単位での整理・検索・閲覧ができない；データ辞書画面が無い |
| **実験ID の明示化** | `protocolId` は存在するが BioDB の実験次元に未マッピング | 会議の核心要件：experiment + participant の二段識別 |
| **BioDB データ閲覧/管理パネル** | 無し | PF 内で BioDB の保存済みデータを閲覧、イベントを管理できない |
| **脳波/実デバイス統合** | Muse adapter はコード実装済み、単体テスト済み | Muse 実機接続・実データ収集・BioDB 格納は未検証。Muse S Athena（Gen 3）は対象外 |
| **分析パイプライン** | プロトタイプ実装・単体テスト済み | 実データと最新統合環境による総合確認が未完了 |
| **可視化** | 履歴曲線・特徴パネル・感情マップを実装済み | ブラウザ手動確認と実デバイスストリーム接続（D9）が未完了 |
| **権限/データセキュリティのプラットフォーム側** | BioDB にはユーザー/権限あり、PF 側に統一管理なし | プラットフォームレベルの役割/権限/監査の統合ビューが無い |
| **条件管理インターフェース** | プロトコルで担うが専用ブラウズなし | 「実験条件一覧」（刺激セット等）のユーザービューが無い |

## 2. 技術アーキテクチャギャップ

| ギャップ | 現状 | 説明 |
|---|---|---|
| **クロスシステム識別の貫通** | PF `protocolId`/participant ↔ BioDB `experiment`/participant の自動マッピング UI が無い | 実験/協力者マッピング層（設定 + 自動導出）が必要 |
| **ストリーミングプッシュ** | Phase 1 はバッチプッシュ | 実行中のリアルタイムプッシュ（バッファ flush + 窓単位 JWT）が無い |
| **PF ↔ BioDB デプロイ連携** | 独立デプロイ | 統一デプロイ/設定（docker オーケストレーション、環境変数、ヘルスチェック）が無い |
| **エラー/リトライ/リカバリ（プッシュ）** | Phase 1 は JWT リフレッシュリトライあり | 断線/再送/冪等の完全な戦略が無い |
| **エクスポート統合** | PF エクスポート独立、BioDB データ独立 | 「PF セッション + BioDB データ」の結合エクスポート/アーカイブが無い |
| **分析/可視化インフラ** | 無し | データパイプライン、計算/トレーニングモジュール、チャートコンポーネントライブラリが無い |
| **統一認証体験** | BioDB は Google OAuth + token；PF は local | プラットフォーム側の統一ログイン/認可ビューが無い |

## 3. データモデルギャップ

| ギャップ | 現状 | 説明 |
|---|---|---|
| **`experiment` タグ次元** | BioDB 時系列は participant+experimenter のみ | 会議の核心：実験次元を追加 |
| **実験メタデータ** | 条件は PF プロトコル、BioDB に実験レベルメタデータ無し | experiment メタデータ（名称、仮説、IRB、プロトコルハッシュ、時刻）が必要 |
| **データ辞書 schema** | PF は graphDataDictionary | 「時系列チャネル → データ辞書」の連携（チャネルリスト → 辞書）が無い |
| **協力者 ↔ BioDB participant マッピング** | `protocol.biodb` + settings マッピング、UI 無し | マッピング管理画面が無い |
| **分析結果の保存** | 無し | 分析結果/特徴量/モデルの保存と書き戻しが無い（BioDB イベントまたは新コレクション） |
| **イベントと実験の関連** | BioDB event は user_id（協力者）あり | event ↔ experiment の関連付け（experiment フィールド追加）が無い |
| **時系列欠落/品質問題** | 無し | 収集品質メタデータ（フレーム落ち率、タイムスタンプ連続性）が無い |

## 4. 優先度順位（影響 vs コスト）

| 優先度 | ギャップ | 影響 | コスト |
|---|---|---|---|
| P0 | `experiment` タグ次元（BioDB の 1 行拡張） | 会議の核心、二段識別の基盤 | 低 |
| P0 | 実験/協力者マッピング UI（PF 設定） | データ識別を利用可能にする | 低 |
| P1 | PF BioDB データ閲覧/管理パネル | プラットフォーム「管理」の実装 | 中 |
| P1 | 実脳波デバイス adapter | 脳波統合 | 中高（ハードウェア依存） |
| P1 | データ辞書連携（channel→辞書） | データの解釈可能性 | 中 |
| P2 | 結合エクスポート/アーカイブ（PF セッション + BioDB） | データ納品 | 中 |
| P2 | 分析パイプライン（前処理/特徴/ML） | プラットフォームの分析 | 高 |
| P2 | 可視化（履歴/リアルタイム/感情マップ） | プラットフォームの可視化 | 中高 |
| P3 | ストリーミングプッシュ | リアルタイム体験 | 中 |
| P3 | プラットフォームレベル権限/監査/統一認証ビュー | コンプライアンス | 高 |
